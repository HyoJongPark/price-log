# 브랜치 병합과 푸시

## 로컬 병합

1. 요청한 작업 브랜치와 대상 브랜치를 정한다. 대상 생략 시 로컬 `main`을 사용한다. `git status --short --branch`, `git worktree list`, source·target의 SHA를 확인한다. 대상이 다른 worktree에 있으면 그 위치의 상태도 확인해 기존 작업을 보존한다.
2. source와 target 사이의 커밋·diff를 읽고 [커밋 전 검사](../commit-changes/SKILL.md)의 기준으로 병합할 **커밋 내용**을 검증한다. 변경이 섞인 작업 트리에서 얻은 통과 결과를 그대로 사용하지 않는다.
3. source가 이미 target의 조상이면 이미 반영된 상태다. target이 source의 조상이면 대상 브랜치가 체크아웃된 worktree를 사용한다. 그런 worktree가 없으면 현재 작업을 보존할 수 있는지 확인한 뒤 대상 브랜치로 전환한다. HEAD의 브랜치명·SHA와 source SHA가 확인한 값과 일치하는지 점검하고 `git merge --ff-only <확인한 source SHA>`로 반영한다. 이력이 갈라져 있으면 양쪽 고유 커밋을 보여주고 병합 커밋이나 rebase 등 이력 처리 방식을 확인한다. 사용자가 방식을 지정했으면 그 범위를 따른다.
4. 병합 과정에서 미커밋 변경을 잃거나 다른 작업에 간섭할 경우 그 위치와 충돌하는 변경을 알린다. 기존 변경을 임의로 stash·reset하지 않는다. fast-forward 후 대상 브랜치의 SHA가 확인한 source SHA와 일치하는지, 작업 트리에 어떤 변경이 남았는지 확인한다. 로컬 병합 요청은 여기서 끝낸다.

## 원격 반영을 요청받았을 때

- 지정한 브랜치와 원격을 확인하고, 원격 ref를 조회해 새로 게시될 커밋과 diff를 검토한다. 새 원격 브랜치라면 게시할 이력 전체를 기준으로 확인한다. 푸시만 요청받은 경우에도 게시할 SHA의 변경에 맞는 [검사](../commit-changes/SKILL.md)를 실행한다. 같은 내용·설정·환경에서 확인한 결과는 재사용하고, 필수 검사가 실패하거나 미실행이면 게시를 보류한다.
- 확인한 로컬 SHA를 지정한 원격 ref에 일반 push한 뒤 `git ls-remote`로 원격 SHA를 대조한다. non-fast-forward로 거절되면 바뀐 이력을 확인한다. 원격 이력 교체까지 명시적으로 요청받은 경우에만 이전 SHA를 로컬 복구 ref에 보존하고 대상 ref와 확인한 이전 SHA를 명시한 lease를 사용한다.
- 결과에는 로컬 병합과 원격 반영 중 실제 수행한 동작, 브랜치·최종 해시, 검증 결과를 적는다.
