# Steam 본편·DLC 카탈로그 수집

`SteamCatalogCollector.collectAll(scheduledAt)`는 본편 목록을 끝까지 읽은 뒤 DLC 목록을 읽는다. 두 목록은 예정 시각이 같아도 각각의 진행 위치를 가진다. 전체 목록은 DB 최초 적재 때 한 번 읽는다. 서버 기동 시 DB의 완료 기록을 확인하며, 재배포해도 이미 완주한 목록의 Steam 페이지는 다시 요청하지 않는다.

1. 목록 종류와 예정 시각으로 `pipeline_execution`에서 회차를 연다. 새 회차는 커서 0에서 시작하고, 완료한 목록은 건너뛴다.
2. Steam에 최대 10,000개 앱을 요청한다. 응답을 받은 뒤 앱 목록과 마지막 앱 ID를 한 트랜잭션에 저장한다.
3. 다음 페이지가 있으면 저장한 앱 ID 다음부터 읽는다. 마지막 페이지까지 저장하면 해당 목록을 `COMPLETED`로 기록한다.

페이지 저장에 실패하면 해당 페이지를 롤백하고 회차를 `FAILED`로 종료한다. 이미 저장한 앱과 커서는 보존된다. 같은 예정 시각의 카탈로그를 다시 호출하면 마지막 커밋 다음부터 이어간다. 최초 적재가 실패하면 다음 기동에서 같은 회차와 커서를 쓴다. 카탈로그를 완주하기 전에는 시간별 변경 수집을 시작하지 않는다. 이후 신규·변경 앱은 매시간 변경 목록에서 발견한다.

## DLC와 본편 연결

최초 적재에서는 본편 목록을 먼저 완주한다. DLC 페이지의 앱 번호를 그대로 한국 상점 `GetItems`에 `include_related_items=true`만 요청한다. 기본 묶음 크기는 260개다. 응답 순서가 달라도 요청한 DLC의 앱 번호로 `related_items.parent_appid`를 대응한다. 카탈로그 일괄 저장 SQL에서 해당 번호의 활성 본편을 찾아 DLC의 `game.parent_game_id`에 내부 키를 기록한다. DLC 이름·연결·최초 목록 커서는 한 트랜잭션으로 커밋한다.

매시간 변경 목록에 나온 DLC도 같은 경로를 탄다. 페이지당 한 번 기존 연결을 확인해 활성 본편에 연결된 DLC의 상점 조회를 생략한다. 같은 페이지에서 DLC로 재분류되는 앱은 부모 후보에서 제외한다. 새 DLC와 아직 연결되지 않은 DLC, 기존 부모가 삭제되거나 DLC로 재분류된 항목만 조회한다. 한국 상점이 부모를 제공하지 않거나 본편이 카탈로그에 없으면 DLC는 이름과 종류만 저장한다. 그 DLC가 다음 변경 목록에 나오면 다시 확인한다. 전체 미연결 DLC를 순회하는 작업은 없다. HTTP 요청 자체가 실패하면 기존 회차 복구 규칙을 따른다.

## 기동 시 최초 가격 적재

기동 시각에 관계없이 카탈로그 적재를 끝낸 뒤 활성 본편 전체의 한국 구매 옵션과 가격을 한 번 관측한다. DB의 `STEAM_PRICE` 완료 기록이 있으면 재배포해도 전체 가격 조회를 건너뛴다. 완료 기록이 없고 중단된 전수 회차가 있으면 그 회차에 고정한 대상과 마지막 저장 위치를 사용한다. 전수 이력이 없을 때만 새 회차를 만든다.

최초 적재 후에는 기동 시와 매시 정각에 변경분을 확인한다. 변경 목록에 나타나지 않은 게임은 마지막으로 확인한 가격과 관측 시각을 유지한다. 서버가 꺼져 있던 동안 시작하고 끝난 할인의 중간 가격은 소급해 채우지 않는다.

가격 수집을 시작하거나 재개할 때는 `pipeline_execution`에서 파이프라인 종류와 예정 시각 `(pipeline, scheduled_at)`으로 회차를 찾는다. 이후에는 그 행의 기본 키 `id`로 배치 진행 위치와 완료·실패 상태를 기록한다. 최초 가격 회차에는 기동 시각을 마이크로초 단위로 쓰고, 변경분 회차에는 정각을 쓴다. 정확히 정각에 기동하면 최초 가격 회차를 정각 1마이크로초 뒤로 구분한다. 두 관측 사이에 같은 상품의 가격이 바뀌어도 이력을 각각 저장한다.

가격 이력은 `price_history`에서 상품과 예정 시각 `(purchase_option_id, slot_at)`마다 첫 관측 한 건을 보존한다. 그래프의 한국 날짜는 실제 관측 시각인 `observed_at`을 기준으로 한다. 한 회차가 자정을 넘길 때도 같은 규칙을 쓴다.

운영 기본값은 `pricelog.collection.daily.batch-size=260`이며 `pricelog.collection.daily.enabled`로 스케줄을 켜거나 끈다. 본편 1,200개를 같은 조건으로 대조한 결과 260개 묶음까지 앱별 결과와 가격이 일치했다. 265개에서는 일부 요청이 HTTP 414로 거절됐다. 414를 받으면 해당 묶음을 반씩 나누고 원래 순서로 합친 뒤 회차 커서를 커밋한다. HTTP 400을 받으면 해당 묶음의 진행 위치를 갱신하지 않고 가격 회차를 `FAILED`로 기록한다. 정상 응답 뒤에는 다음 배치가 준비되는 대로 요청한다. 429에 따른 대기는 수집기의 DB 트랜잭션 밖에서 수행한다.

## 시간별 변경 목록과 가격 확인

기동 시와 이후 **매시 정각(한국 시각)**에 변경 목록을 읽는다. 변경 이력이 없는 DB에서는 완주한 DLC 전수 회차 중 가장 이른 예정 시각을 찾아 그 한 시간 전부터 읽는다. DLC 전수는 같은 회차의 본편 목록을 완주한 뒤에 끝난다. 이후에는 본편·DLC 변경 목록을 모두 읽고 가격 대상을 확정한 마지막 회차의 예정 시각에서 한 시간을 뺀다. 예를 들어 10시 회차가 목록을 완주하고 11시 조회가 실패한 뒤 이틀 후 재기동하면, 이틀 전 09:00부터 다시 읽는다. 한 시간은 뒤늦게 노출된 변경을 다시 발견하기 위한 운영 여유다. 겹치는 본편은 가격을 재확인할 수 있다. 재기동 시 이미 완료한 정각 회차는 건너뛴다. 단일 스케줄러에서 전수 가격 수집이나 429 대기가 길어지면 다음 변경 조회의 실제 시작이 늦어질 수 있다.

`GetAppList`에 `if_modified_since`를 Unix 초로 보내고 본편·DLC별로 `last_appid`를 넘겨 끝까지 읽는다. 반환된 본편과 DLC는 카탈로그에 반영하고, 본편만 한국 상점에서 구매 옵션과 원화 가격을 다시 확인한다. Steam의 앱 변경 신호에는 이름 등 가격 이외의 변경도 포함된다. `price_change_number`는 가격 변경 가능성을 나타내며 한국 패키지·번들의 실제 원화 가격은 한국 상점 응답에서 확인한다. Steam 변경 신호가 오지 않은 구매 옵션의 가격은 오래된 값으로 남을 수 있다. [Steamworks GetAppList](https://partner.steamgames.com/doc/webapi/IStoreService#GetAppList)

`pipeline_execution`의 `STEAM_CHANGED_APPS` 회차에서 `target_ids`가 NULL이면 아직 목록을 완주하지 못한 상태다. 목록 조회 도중 중단되면 저장한 앱은 유지하고 해당 시간 구간을 첫 페이지부터 다시 읽는다. 두 목록을 끝까지 읽으면 변경 본편과 직전 목록의 미확인·미처리 본편을 합쳐 대상을 고정한다. 빈 배열은 조회할 가격이 없다는 뜻이다. 상점은 전수와 같은 배치 크기·429 대기·414 분할·미확인 재조회 로직을 사용한다. 같은 변경 회차를 다시 호출하면 저장한 위치부터 재개한다. 다음 변경 회차에서는 남은 대상과 새로 변경된 본편을 합친다. 새 회차는 이렇게 정한 대상의 첫 묶음부터 읽는다.

## 한국 상점 구매 옵션 조회

카탈로그에서 읽은 본편의 `game.steam_app_id` 목록을 `SteamStoreClient.getPurchaseOptions(steamAppIds)`에 전달하면 한국 상점에 HTTP 요청을 한 번 보낸다. 응답의 앱 ID를 요청 ID와 맞춰 게임별 구매 옵션 목록(`purchaseOptions`)과 Steam 기본 옵션(`bestPurchaseOption`)을 읽는다. 패키지와 번들은 같은 숫자 ID를 쓸 수 있어 종류와 ID를 함께 비교한다. 이름이 없는 상품도 ID로 식별한다.

본편은 같은 요청에 `include_assets=true`를 보내고, 응답의 `assets.asset_url_format`에 있는 `${FILENAME}`을 기본 파일명 `assets.header`로 치환해 Steam CDN 주소를 만든다. 기본 파일명이 없거나 비어 있을 때만 `assets.header_2x`를 사용한다. 이 주소를 `game.image_url`에 저장한다. 두 헤더가 모두 없거나 한국 상점에서 확인되지 않으면 마지막 이미지를 보존한다. 이미 전수를 마친 DB에서는 각 본편의 상점 응답을 다시 받을 때부터 채워진다.

같은 본편 배치에서 `include_basic_info=true`로 요청해 `basic_info.short_description`에 내용이 있을 때 `game.description`을 갱신한다. 한국어로 요청하되 Steam이 반환한 원문을 보존한다. 설명이 누락되거나 공백이면 마지막 값을 유지하며, 한 번도 확인되지 않았다면 `NULL`이다. 이미 전수를 마친 DB에서는 다음 상점 조회 대상이 된 본편부터 채워진다.

같은 배치에서 `include_release`와 `include_supported_languages`도 요청한다. `release_date`는 Steam 출시 시각을 한국 시간으로 환산한 달력 날짜다. 출시 예정 게임은 공개 형식이 `date_full`일 때만 날짜를 저장한다. 월·분기·연도만 공개하면 그 단위의 문구를, 사용자 지정 문구가 있으면 원문을 `release_text`에 저장한다. 날짜를 철회하면 기존 날짜도 비운다. `coming_soon`은 원천의 출시 예정 표시이며 현재 날짜로 추정하지 않는다. 출시 정보 전체가 누락되면 이전 값을 유지한다. 공개 상점 문구와 한국 시간 달력 날짜는 하루 차이 날 수 있다. Dota 2의 한국어 상점 표본에는 2013년 7월 9일로 표시됐고, Steam 출시 시각을 한국 시간으로 환산하면 7월 10일이다. [Steam 출시일 공개 형식](https://partner.steamgames.com/doc/store/release_dates)

언어 목록의 한국어 항목(`elanguage=4`)에서 인터페이스·자막·음성을 읽어 `korean_support_text`에 저장한다. 목록은 있지만 한국어 지원이 없으면 ‘미지원’, 목록을 확인하지 못하면 이전 값을 유지한다. 출시와 언어는 각각 독립적으로 갱신한다.

기본 지정이 생략되면 전체 목록을 반환하고 `bestPurchaseOption`은 `null`이다. 옵션이 하나인 경우에도 같다. Steam이 기본값을 지정했는데 같은 종류·ID의 항목이 없거나 둘 이상이면 조회가 실패한다. 앱의 무료 표기와 각 상품의 종류·ID·이름·확인된 가격을 읽는다.

## 게임별 구매 옵션 저장

`SteamStoreCollector.collectPurchaseOptions(steamAppIds, slotAt)`는 확인된 게임을 요청 순서대로 저장한다. 트랜잭션 하나에 해당 묶음에서 확인한 게임들의 무료 표기·구매 옵션·가격을 반영한다. 반환된 맵에는 정상 조회한 앱과 Steam이 한국 판매 제한 또는 상점 미노출을 명시한 앱이 들어간다. 실패 사유를 판정할 수 없거나 응답이 누락·중복되거나 해석에 실패하면 해당 게임은 저장을 건너뛰어 기존 연결과 대표 지정을 유지한다. 정상 응답에서 구매 옵션이 비어 있으면 그 게임의 활성 연결을 닫는다. HTTP 요청 자체가 실패하면 해당 묶음의 저장을 시작하지 않는다. `purchase_option`은 종류(PACKAGE·BUNDLE)와 Steam ID로 활성 판매 상품을 식별한다. 여러 게임이 같은 상품을 팔면 상품 한 행을 공유하고, `game_purchase_option`은 `game_id`와 `purchase_option_id`로 게임과 구매 옵션을 다대다로 연결한다.

게임별 한국 상점 노출 상태를 `game.store_visibility`에 저장한다. 기존 행과 아직 조회하지 않은 앱은 `NULL`이다.

| 같은 앱 ID의 한국 GetItems 응답 | 저장값 | 처리 |
| --- | --- | --- |
| 정상 앱 응답 | `VISIBLE` | 구매 옵션·무료 여부·가격을 반영한다. 이전에 제한됐던 앱도 같은 규칙으로 갱신한다. |
| `success=15`이고 `unvailable_for_country_restriction=true` | `REGION_RESTRICTED` | 한국 판매 제한을 기록한다. 동시에 `visible=false`여도 이 판정이 우선한다. |
| `success=15`, 국가 제한 표시 없음, `visible=false` | `HIDDEN` | 한국 상점에서 페이지가 보이지 않는다는 관측을 기록한다. 영구 판매 종료 여부는 미확인이다. |
| ID 누락·중복, 모호한 실패 등 | 마지막 값 유지 | 회차의 미확인 ID로 남겨 재시도한다. |

제한·미노출 응답은 노출 상태만 갱신한다. 해당 회차에서 처리를 마치고, 다음 정기 관측에서 다시 확인한다. 기존 무료 여부, 대표 구매 옵션, 현재가와 가격 이력은 보존한다.

`game_purchase_option.is_best_option`은 Steam이 해당 게임에서 지정한 옵션 한 건에만 true다. 정상 응답에서 기본 지정이 생략되면 대표 선택을 해제한다. 목록에서 빠진 상품은 해당 게임의 연결만 닫는다. 조회가 실패하거나 지정된 옵션을 목록에서 식별할 수 없으면 마지막 성공 상태를 유지한다.

한 배치에 등장한 상품의 종류와 Steam ID를 짝지어 중복을 제거하고, 현재 판매 구간을 한 번에 조회한다. 배치 전체에 구매 옵션이 없으면 이 조회를 건너뛴다. 새 상품은 저장 직후 같은 배치의 다른 게임에서도 재사용한다.

일반 JPA 조회에서는 소프트 삭제된 행을 제외한다. 상품의 현재 판매 구간은 `deleted_at IS NULL AND sale_ended_at IS NULL`로 찾으며, 같은 종류·Steam 번호에는 이 조건을 만족하는 상품이 최대 하나다. 판매가 끝난 상품도 소프트 삭제되지 않았다면 내부 상품 ID로 과거 가격을 조회할 수 있다.

한국 상점의 정상 응답에서 모든 게임 연결이 사라져도 상품 자체의 판매 종료는 자동 확정하지 않는다. 무료 게임이나 구매를 일시 중단한 게임에서도 옵션이 비어 있을 수 있다. [Steamworks 판매 종료 안내](https://partner.steamgames.com/doc/store/retire_app)

상품의 한국 판매 종료가 별도로 확인되면 `GamePurchaseOptionService.endSale`이 해당 내부 상품 ID에 `sale_ended_at`을 기록하고 연결된 모든 게임의 활성 연결을 같은 트랜잭션에서 닫는다. 종료 후 시작한 회차에서 같은 종류·Steam 번호를 다시 발견하면 새 상품 행을 만든다. 종료 시각과 같거나 그보다 이른 회차를 재개할 때는 `slot_at`을 기준으로 이전 구간을 식별한다. 소프트 삭제한 상품은 이 판단에서 제외한다.

- 배치마다 종료 상품을 종류·Steam 번호로 정리하고, 종료 전 구간에 연결됐던 게임(회차 전에 연결이 끝난 경우 제외)과 같은 상품의 재판매 구간에 현재 연결된 게임을 한 번 조회해 집합으로 만든다. 이 게임이거나 응답에 종료 상품이 있으면 현재 구매 옵션·대표·무료 표기를 유지한다. 재판매 후 처음 해당 상품을 제공한 게임도 과거 회차의 빈 응답으로 대표 연결을 잃지 않는다.
- 이 응답으로 재판매 상품의 가격을 쓰거나 새 상품을 만들지 않는다. 함께 온 다른 상품이 기존 활성 구간으로 확인되면 그 회차 가격만 이력에 추가한다. 현재가는 유지한다.
- 나머지 게임은 같은 묶음에서 평소대로 저장한다. 패키지와 번들은 Steam 번호가 같아도 다른 상품이다.

## 가격 수집 중단 후 재개

`SteamStoreCollector.collectAll(slotAt, batchSize)`는 회차를 처음 열 때 활성 본편의 Steam 앱 ID를 오름차순으로 확정한다. `pipeline_execution`의 `STEAM_PRICE` 행 하나에 대상 목록(`target_ids`), 다음에 처음 조회할 위치(`next_index`, 0부터 시작), 이미 요청한 미해결 앱(`failed_ids`)을 둔다. 같은 예정 시각에 실행 중이던 작업은 고정된 대상과 진행 위치를 복원한다. 대상 확정 이후에 추가된 본편은 변경 목록에서 발견해 가격을 조회한다. 단일 서버에서 기동 시 전수의 완료·재개 여부를 판단하고, 정기 스케줄은 변경분만 실행한다.

Steam 응답을 받은 뒤 한 묶음의 게임·상품·가격 이력과 진행 위치를 한 트랜잭션으로 저장한다. 앱이 누락되면 그 ID를 남기고 다음 묶음으로 진행한다. 마지막에 미해결 ID만 한 차례 더 조회한다. 그래도 남으면 회차는 `FAILED`, 전부 해결하면 `COMPLETED`다. DB 쓰기나 요청 자체가 실패하면 마지막으로 커밋한 위치에서 멈춘다. 프로세스 종료로 `RUNNING`이 남아도 같은 위치에서 재개한다.

| 30개 요청 중 1개 누락 | 같은 회차에서 다시 조회할 앱 |
| --- | --- |
| 가격과 진행 위치를 커밋하기 전에 중단 | 30개 |
| 29개를 반영하고 미해결 ID를 기록한 뒤 중단 | 누락된 1개 |
| 나머지 1개까지 반영 | 0개 |

목록·상점 HTTP 연결 제한은 5초, 응답 읽기 제한은 30초다. 시간 초과가 발생하면 해당 회차에 실패를 기록한다. 전수는 다음 기동에서, 변경분은 다음 정각에 진행 상태에 따라 이어간다.

429를 받으면 목록은 같은 페이지를, 상점은 원래 요청한 앱 묶음을 15초, 30초, 45초 간격으로 최대 세 번 재시도한다. 414로 분할한 도중 429가 발생하면 이미 조회한 앞부분도 다시 요청할 수 있다. 두 부분의 조회가 모두 끝난 후 한 배치로 저장한다. 첫 요청을 포함해 총 네 번이다. 네 번째 요청도 429이면 예외를 호출자에게 전달한다.

요청 재시도까지 소진한 429에는 전수와 변경분 모두 같은 회차 정책(`steamCollection`)을 사용한다. 5분 간격으로 최대 세 번 재개한다. 기동 시 카탈로그와 가격은 각각 독립된 회차이며, 시간별 변경 목록과 그 본편의 가격은 한 회차여서 재개 횟수도 공유한다.

| 429가 발생한 단계 | 5분 뒤 같은 회차의 재개 위치 |
| --- | --- |
| 최초 본편·DLC 목록 | 완료한 목록을 건너뛰고 중단된 종류의 마지막 저장 커서 다음 페이지 |
| 최초 본편 가격 | 고정한 대상 중 첫 미저장 묶음 또는 남은 미확인 앱 |
| 시간별 변경 목록 | 동일한 조회 시작 시각으로 본편·DLC의 첫 페이지부터 다시 조회 |
| 시간별 변경 본편 가격 | 이미 확정한 대상 중 첫 미저장 묶음 또는 남은 미확인 앱 |

세 번 재개해도 429가 계속되면 해당 회차는 `FAILED`로 남는다. 미완료 전수는 다음 기동에 재개한다. 변경 목록을 완주하기 전에 실패했으면 다음 정각에 마지막으로 완주한 목록 기준으로 구간을 다시 읽는다. 변경 가격 단계에서 실패했으면 미확인·미처리 본편을 다음 정각의 대상에 합친다. HTTP 요청과 재시도 대기는 DB 저장 트랜잭션 밖에서 진행한다.

## 무료 플레이와 상품 가격의 기준

`SteamStoreCollector.collectPurchaseOptions(steamAppIds, slotAt)`는 카탈로그에 있는 앱의 한국 상점 응답을 한 번 읽고, `IStoreBrowseService/GetItems`의 `response.store_items[].is_free`를 `game.is_free`에 저장한다. `true`는 무료 플레이, 명시된 `false`는 무료 플레이 아님, `NULL`은 미확인이다. 상점을 조회하기 전이거나 성공 응답에 필드가 생략된 경우에는 무료 여부를 추정하지 않는다. 필드가 생략된 새 성공 응답은 이전 표기를 미확인으로 바꾸고, 조회 실패는 마지막 값을 보존한다. 구매 옵션 개수와 0원 라이선스는 이 판단에 사용하지 않는다. 최초 적재와 변경분 수집에서 확인한 본편의 무료 표기도 함께 갱신한다.

출시 예정 여부(`game.coming_soon`)와 무료 플레이(`game.is_free`)는 동시에 성립할 수 있고, 한 게임의 일반판과 디럭스판은 서로 다른 가격에 팔릴 수 있다. 한국 원화 현재가·정가·할인율·할인 종료 시각의 원천은 구매 옵션별 `formatted_final_price`, `formatted_original_price`, `discount_pct`, `active_discounts[].discount_end_date`다. 판매가·정상가·할인 종료 시각은 해당 구매 옵션과 관측 시각에 연결해 저장한다. 원천 할인율(`discount_pct`)은 별도 컬럼에 저장하지 않는다.

## 앱 응답에서 현재가와 이력 저장

수집기는 한 묶음의 앱에 같은 관측 시각을 부여한다. 여러 게임에서 같은 상품을 판매하면 응답 도착 순서와 관계없이 요청 순서에서 먼저 확인한 가격을 그 회차에 기록한다. 각 옵션의 종류와 Steam ID로 판매 상품을 찾거나 생성하고 상품 연결, 대표 지정, 가격을 같은 트랜잭션에서 반영한다.

한국 상점의 원화 표시가에서 원 단위 정수를 읽어 저장한다. 예를 들어 `₩ 9,420`은 9420원으로 저장한다. 명시적 0원도 포함한다. 정상가와 할인 종료 시각은 확인된 값만 저장한다. 현재가를 확인할 수 없거나 무료 라이선스·정기 결제인 옵션도 상품 연결을 유지하며 가격 관측은 건너뛴다.

같은 판매 구간과 예정 회차(`slot_at`)에서 처음 확인한 가격을 `price_history`에 추가한다. 새 관측이면 `purchase_option`에 마지막 확인 판매가·정상가·할인 종료 시각·확인 시각(`price_observed_at`)을 반영한다. 홈과 상세의 현재가는 이 상품 행에서 읽고 그래프는 같은 판매 구간의 이력을 읽는다. 재실행하거나 여러 게임이 같은 상품을 제공해도 회차당 첫 성공값을 보존한다. 다음 회차에서 같은 가격이 확인되면 새 이력이 생긴다. 실패한 관측은 마지막 확인 가격과 시각을 유지한다.

## 본편 태그

서버는 기동 시 한국어 태그 사전을 받고 이후 24시간마다 확인한다. `IStoreService/GetTagList`에 마지막으로 DB에 반영한 `version_hash`를 보내고, 같은 버전의 빈 응답이면 쓰기를 생략한다. 새 사전을 확인하기 전에 게임에서 새 ID를 발견하면 이름을 비워 두었다가 다음 사전 응답에서 채운다.

기존 본편 상점 배치는 `include_tag_count=20`로 가격과 태그 ID를 함께 읽는다. 최초 전수와 시간별 변경분 모두 같은 경로를 쓴다. 본편마다 태그를 응답 순서대로 최대 20개까지 `game_tag`에 묶어 반영한다. 표시 이름은 `tag.name_ko`로 조회한다. 공개 본편의 정상 응답에 `tagids: []`가 명시되면 기존 태그 연결을 모두 해제한다. 태그가 누락되거나 노출 상태의 형식이 잘못됐거나 한국 상점에서 볼 수 없으면 이전 연결을 보존한다. 판매 종료 전 가격 회차를 재개해도 본편 태그에는 이번 상점 응답의 순서를 반영한다. 태그 검색은 저장된 태그 전체를 대상으로 한다. 일반 카드는 `display_order` 1~5, 좁은 카드는 1~3에서 한국어 이름이 확인된 태그를 순서대로 표시한다. [화면 표시 기준](product.md#본편-태그-검색과-카드-표시)

이전에 태그를 5개씩 받은 게임은 다음 상점 조회 때 최대 20개로 갱신된다. 이미 전수 가격 적재를 마친 DB는 배포할 때 한 번 태그를 보완할 수 있다. 정기 수집 프로세스를 멈춘 상태에서 저장소 루트의 다음 명령을 실행한다. 보완은 활성 본편을 앱 번호 순으로 돌며 태그만 읽고 저장한다. 장시간 중단되면 로그에 마지막으로 반영된 Steam 앱 번호를 `after-app-id`에 넣어 재개한다. 미확인 앱 수는 배치별 요청 수와 확인 수의 차이로 알 수 있다. 정상 서비스로 돌아오면 사전과 변경 게임은 자동으로 갱신된다.

```sh
(cd backend && ./gradlew bootJar && java -jar build/libs/price-log-0.0.1-SNAPSHOT.jar \
  --spring.main.web-application-type=none --pricelog.collection.daily.enabled=false \
  --pricelog.collection.tag-backfill.after-app-id=0)
```
