# 프라이스로그 화면과 동작

사용자는 인기 게임을 둘러보거나 이름으로 찾은 뒤, 어떤 게임인지와 지금의 한국 Steam 가격이 괜찮은지 판단하러 온다.

아래 코드·테스트·캡처 경로는 PoC 루트 기준이다. 현재 체크아웃에서는 저장소 루트 기준 `../../game-shelf-kr/`에 있다. 경로가 달라졌으면 원본 디렉터리나 `game-shelf-kr.zip`을 푼 위치에서 같은 상대 경로를 찾는다. PoC의 `README.md` 앞부분에는 현재 동작이, ‘이전 설계 이력’ 절에는 폐기한 실험도 있다. 변경할 화면은 아래 결정과 해당 코드·테스트를 함께 확인한다.

| 화면 | 유지할 사용자 경험 | PoC에서 찾아볼 곳 |
| --- | --- | --- |
| 홈·탐색 | 홈에서 인기 순위와 게임 이름 검색을 바로 이용한다. 순위는 수록한 본편에서 관측한 Steam 전 세계 동시 접속자 수를 비교한다. 표본 수와 관측 시각(KST)을 함께 표시하고 시각이 없으면 미확인으로 표시한다. 메뉴는 홈 → 스팀 캘린더 → 위시리스트 순서다. 스포트라이트 이미지를 누르면 상세로, 좌우로 끌거나 스와이프하면 다른 게임으로 간다. 검색 약칭 확장은 후순위다. | `public/app.js`의 `pageshell`, `rankPanel`, `mountSpotlight`, `searchPage`. 동률·결측 처리와 전일 대비 증감률의 비교 조건은 `public/rank.js`와 `test_rank.cjs`. |
| 가격 미리보기 | 마우스를 올리거나 게임 링크에 키보드 포커스를 두면 해당 게임의 그래프가 열린다. 키보드로 연 미리보기는 Escape로 닫을 수 있다. 터치에서는 표시 금액을 탭해 열고 닫는다. 카드마다 ‘가격 기록’ 버튼을 반복하지 않는다. 한 건이면 확인 날짜·금액과 점 하나, 두 건부터 같은 그래프에 선을 그린다. 관측이 0건이고 현재가만 확인됐으면 금액과 함께 날짜별 기록이 없음을 안내한다. 현재가도 확인되지 않았으면 아직 확인한 한국 Steam 가격이 없다고 표시한다. | `public/insights.js`의 `interact`, `previewContent`, `spark`. |
| 게임 상세 | 제목 아래 소개·출시일·장르·한국어 지원 여부를 둔다. 그래프의 선택점은 그날 확인한 원화 판매가다. 현재 가격 분석은 현재가와 선택 기간의 같은 상품 관측 최저가를 비교한다. 과거 점으로 옮겨도 현재가는 유지한다. 단 한 건으로 역대 최저·할인 주기를 단정하지 않는다. | `public/app.js`의 `detail`, `public/insights.js`의 `renderHistory`, `public/price-cycle.js`의 `panel`. `test_cycle.cjs`에 선택일·기간·0원·다른 상품/통화 사례가 있다. |
| 구매자 평가·DLC | Steam 구매자 리뷰 수와 긍정 비율을 일간·주간·월간으로 전환한다. 비율은 구간의 긍정 건수 합을 전체 건수 합으로 나누고, 일부 기간만 수록했으면 표시한다. 본편에 연결된 DLC는 이미지·상품명·본편 필요 표시를 함께 보여준다. | `public/reviews.js`의 `groupReviews`, `reviewPanel`, `test_insights.py`. DLC는 `public/app.js`의 `relatedContent`. |
| 스팀 캘린더 | 게임 출시와 공식 할인 일정을 한 달력에서 본다. 계절 세일·테마 축제·퍼블리셔 행사 등은 공식 출처를 붙여 수동 등록할 수 있다. 날짜 칸은 선택한 날만 강조하고 월 전체 보기로 돌아가면 해제한다. 게임 할인과 행사 날짜가 겹친다는 사실만으로 그 게임의 행사 참여를 확정하지 않는다. | `public/app.js`의 `calendarWeeks`, `calendar`. 일정의 시작·종료 시각과 출처는 `public/sale-events.json`. |
| 계정·위시리스트 | 찜과 가격 하락 구독은 각각 켜고 끌 수 있다. 찜 해제 후에도 구독과 기존 수신함을 유지한다. PoC에서 알림을 켤 때 찜까지 생성하는 동작은 새 설계에서 분리한다. 로그인 버튼은 게임 이름 검색 오른쪽에 둔다. 로그인 성공 시 게스트의 찜·알림 이력을 비우고 해당 계정의 기존 상태를 불러온다. 실패하면 게스트 상태를 유지한다. 카카오·네이버·구글은 PoC에서 모의 로그인이다. | `public/app.js`의 `openAccount`, `shelf.py`의 `start_session`, `mock_login`. 첫 로그인·재로그인·실패는 `test_shelf.py`의 `test_guest_history_clears_on_first_and_returning_login`. |
| 가격 하락 알림 | 사이트 안에서 수신한다. 헤더 벨에 미확인 건수가 보이며, 벨이나 수신함을 여는 동안은 읽음 상태를 바꾸지 않는다. 알림을 따라 상세에 도착하면 그 알림 ID 한 건만 읽음이 된다. 같은 게임의 다른 알림은 유지하며 목록에서 개별·모두 읽음을 선택할 수도 있다. 이메일 발송은 범위 밖이다. | `public/app.js`의 `noticeRow`, `load`, `acknowledgeNotices`. 소유자별 읽음 기록은 `shelf.py`의 `mark_read`, 재시도·격리는 `test_shelf.py`. |

## 화면 대조

`evidence/discount-cycle/` 안의 다음 캡처는 대표 상태를 보여준다. 입력 방식이 바뀌면 마우스·키보드·터치 중 영향받는 방식을 골라 실행 중인 화면에서 확인한다.

- `home-ff7-preview-1440.png`, `home-ff7-preview-390.png` — 데스크톱 카드 옆의 미리보기와 모바일 카드 행 아래의 미리보기.
- `price-analysis-1440.png`, `price-analysis-390.png` — 과거 선택가와 현재가가 다른 상태. 데스크톱에서는 같은 줄의 두 패널 경계·간격이 맞고, 모바일에서는 현재 가격 분석 다음에 가격 추이가 이어진다.
- `calendar-selected-320.png`, `explicit-read-bell.png` — 행사 기간과 선택 날짜의 강조 차이, 같은 게임에서 발생한 여러 미확인 알림.

`catalog.json`, `public/observations.json`은 특정 시점의 표본이다. `shelf.py`의 `demo`는 알림 동작을 재현한다. 운영 화면에서 가격·순위·리뷰를 제공할 때는 외부 개발자가 이용할 수 있는 공식 문서에서 제공 항목과 접근 조건을 먼저 확인한다. 원천이 제공한 값, 직접 관측해 쌓은 이력, 공식 공지에서 수동 등록한 일정을 구분하고 상품 식별자·출처·관측 시각을 대조한다.
