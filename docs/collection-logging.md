# 수집 로그 운영

`prod` 프로필은 표준 출력과 `PRICELOG_LOG_DIR/pricelog.log`에 기록한다. 경로를 지정하지 않으면 실행 디렉터리의 `./logs`를 사용한다.

## 실패 확인

| 로그 | 확인할 내용 |
| --- | --- |
| `수집 작업 실패` | 스레드 이름으로 실패한 수집 작업을 좁힌다. 공통 핸들러는 검증 사유, HTTP 상태 또는 예외 타입을 한 번 기록한다. |
| `가격 재조회 후에도 미수집 앱이 남았습니다` | 예외 없이 FAILED로 끝난 가격 회차다. 로그의 회차 ID로 `pipeline_execution.failed_ids`를 조회한다. |
| `상점 응답 해석 실패` · `Steam 구매자 평가 미수집` | 한 앱의 예외를 처리하고 수집을 계속한 경우다. 앱 ID와 함께 수집 코드가 판정한 사유를 확인한다. 외부 HTTP 오류는 상태 코드, 그 밖의 오류는 예외 타입으로 기록한다. |

## 보관과 접근

| 항목 | 운영 규칙 |
| --- | --- |
| 운영 파일 | 날짜가 바뀌거나 10MB에 도달하면 gzip으로 회전한다. 한국 날짜 기준 최대 14개 일 단위 보관 구간, 압축 아카이브 총 100MB 중 먼저 닿는 제한을 적용한다. 현재 쓰는 파일은 아카이브 한도 밖이다. 정리는 회전 및 프로세스 시작 때 수행한다. |
| 보관 기간 근거 | 같은 게임을 주 1회 읽으므로 연속 두 회차를 조사할 기간을 잡았다. 오류 폭증으로 100MB를 넘으면 오래된 파일이 먼저 지워진다. |
| 재배포 | `SPRING_PROFILES_ACTIVE=prod`와 `PRICELOG_LOG_DIR`을 설정한다. 앱 실행 계정이 쓸 수 있는 서버 디렉터리를 만들고 배포본 밖에 둔다. 컨테이너에서는 같은 위치에 볼륨을 연결한다. 컨테이너 교체 후 직전 회차 파일도 보이는지 확인한다. |
| Docker 표준 출력 | `docker logs`용 짧은 사본은 아래처럼 컨테이너당 5MB × 3개로 제한한다. 실제 보관본은 볼륨에 있는 운영 파일이다. 배포 Compose의 **백엔드 서비스**에 적용한 뒤 컨테이너를 재생성한다. 현재 저장소의 개발 Compose는 PostgreSQL 전용이다. |
| 접근·삭제 | 서버에서 앱 계정과 운영자만 읽게 디렉터리를 0750, 서비스 umask를 0027로 설정한다. 사고 조사에 복사한 발췌본은 접근이 제한된 위치에 두고 조사 종료 시 삭제한다. 원본을 Git·공개 채널에 올리지 않는다. |
| 기록 범위 | 앱·상품 ID, 상태 코드, 건수, 제한된 사유만 남긴다. 원천 본문, 쿼리스트링, 인증 헤더, DB 접속 문자열, 리뷰 본문, 계정 식별자는 수집 로그에 출력하지 않는다. 운영에서 HTTP 와이어·SQL 바인드 디버깅을 켜지 않는다. |

```yaml
logging:
  driver: local
  options:
    max-size: "5m"
    max-file: "3"
```
